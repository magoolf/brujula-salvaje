#
# Por qué se mantiene el archivo (vacío de reglas) y el flag --err-ignore en ci.yaml
#   Es el punto ÚNICO y versionado por el que se puede aceptar una excepción del gate de contrato,
#   análogo a .trivyignore (RSK-OPS-001). Mantenerlo evita que una excepción futura se introduzca
#   por una vía paralela (otro flag, otro archivo, relajar --fail-on). Un archivo sin reglas no
#   ignora nada: todo hallazgo de severidad "error" bloquea el CI (--fail-on ERR, TKT-OPS-010).
#
# Cómo añadir una excepción (solo con DEC-AUTO registrada y, si oculta un riesgo HIGH/CRITICAL,
# aprobación humana, CLAUDE.md §0.5)
#   - Una línea por hallazgo, precedida de un comentario con ticket, DEC-AUTO, motivo y ticket de
#     retirada. NO es una expresión regular (oasdiff v1.32.1, checker/ignore.go, MatchIgnore): la
#     línea, en minúsculas, debe contener el método y la ruta exactos (método, un espacio y la ruta, con la
#     ruta como primer campo que empieza por "/") y el texto exacto, sin colorear, del hallazgo tal como lo
#     imprime oasdiff (argumentos entre comillas invertidas). Sin relleno: minimiza coincidencias
#     accidentales con otros hallazgos.
#   - Los comentarios ("#") de este archivo no contienen "método + espacio + ruta", así que no casan
#     con ningún hallazgo (comprobado en TKT-OPS-021: con este archivo, 0 hallazgos ignorados).
